````markdown
# Grafana IDS Dashboard

## Overview

The Grafana IDS Dashboard provides a centralized visualization layer
for security events generated by Suricata.

The dashboard queries Suricata events stored in Grafana Loki through
LogQL.

The main Loki selector is:

```text
{job="suricata"}
```

Alert events are filtered using:

```text
{job="suricata"}
| json
| event_type="alert"
```

---

## Dashboard Purpose

The dashboard is designed to provide a quick overview of:

- Alert volume
    
- Alert severity
    
- Alert signatures
    
- Source IP addresses
    
- Destination IP addresses
    
- Network protocols
    
- Alert activity over time
    
- Recent Suricata alerts
    
- Rule/SID distribution
    

The dashboard is intended for laboratory monitoring and demonstration.

---

## Dashboard Structure

The current dashboard contains the following panels:

```text
1. Total Alerts
2. Top Alert Signatures
3. Alert Severity
4. Top Source IP
5. Top Destination IP
6. Alert Timeline
7. Recent Suricata Alerts
8. SID Distribution
9. Protocol Distribution
```

The previously considered Signature Distribution panel was not included  
because its information was too similar to Top Alert Signatures.

---

## 1. Total Alerts

### Purpose

Displays the total number of Suricata alert events within the selected  
Grafana time range.

The value changes according to the dashboard time range.

For example:

```text
Last 15 minutes
```

shows alerts generated during the previous 15 minutes.

### Data Source

```text
Loki
```

### Event Type

```text
alert
```

This panel provides a quick indication of the current alert volume.

---

## 2. Top Alert Signatures

### Purpose

Displays the most frequently triggered Suricata alert signatures.

The panel helps identify which detection rules generate the most alerts.

Example signatures include:

```text
LAB HTTP TEST
LAB TCP PORT 80 TEST
LAB Path Traversal Attempt
LAB Suspicious HTTP User-Agent
LAB ICMP Host Discovery Attempt
```

### Interpretation

A high count does not automatically indicate a more dangerous event.

For example, SID `1000003` is intentionally broad and may generate  
more alerts because it matches generic HTTP traffic.

## LogQL Approach

The dashboard uses Loki LogQL queries to extract structured fields from  
Suricata EVE JSON.

Base selector:

```text
{job="suricata"}
```

Alert filter:

```text
{job="suricata"}
| json
| event_type="alert"
```

The JSON parser exposes fields such as:

```text
src_ip
dest_ip
proto
alert_signature_id
alert_signature
alert_severity
```

These fields are then used by individual dashboard panels.

---

## Recent Alert Query

The Recent Suricata Alerts panel uses:

```text
{job="suricata"}
| json
| event_type="alert"
| line_format "{{.src_ip}} → {{.dest_ip}} | {{.proto}} | SID {{.alert_signature_id}} | {{.alert_signature}} | severity={{.alert_severity}}"
```

This produces a concise alert representation.

Example:

```text
10.0.2.15 → 172.66.147.243 | TCP | SID 1000009 | LAB Path Traversal Attempt | severity=1
```

```

## Time Range

The dashboard supports Grafana's standard time range selector.

A commonly used laboratory range is:

```text
Last 15 minutes
```

The time range affects panels that calculate event counts and  
distributions.

Therefore, panel values can change as new traffic is generated or as  
the selected time range changes.

---

## Alert Overlap

A single network request can trigger multiple Suricata rules.

For example, an HTTP request may match:

```text
LAB HTTP TEST
LAB TCP PORT 80 TEST
LAB HTTP EXAMPLE.COM TEST
LAB HTTP GET EXAMPLE.COM TEST
LAB EXACT HTTP GET EXAMPLE.COM ROOT TEST
```

This means the total number of alerts can be greater than the number of  
individual network requests.

This is expected IDS behavior.

---

## Dashboard Interpretation

The dashboard should be interpreted as an operational overview rather  
than a direct statement that every alert represents malicious activity.

For example:

```text
High Alert Count
```

does not necessarily mean:

```text
High Attack Severity
```

Similarly:

```text
High SID Count
```

does not necessarily mean:

```text
High Security Risk
```

The context of the rule, traffic, severity, and destination should be  
considered together.

## Dashboard Design Decision

The dashboard intentionally avoids adding redundant visualizations.

The Signature Distribution panel was considered during development but  
was not included in the final dashboard because it provided information  
too similar to Top Alert Signatures.

The final dashboard prioritizes:

```text
Overview
+
Severity
+
Network Context
+
Rule Context
+
Timeline
+
Recent Alerts
```

This keeps the dashboard lightweight and focused.

---

## Conclusion

The Grafana IDS Dashboard provides a functional visualization layer for  
the Lightweight Suricata IDS Lab.

It combines alert volume, severity, network context, rule information,  
protocol information, timeline activity, and recent events into a  
single monitoring interface.

The dashboard is backed by Loki and LogQL and uses structured Suricata  
EVE JSON fields for visualization.

The final design intentionally avoids redundant panels while retaining  
the information required to understand the laboratory's IDS activity.
````
